## Проблема

Двойной клик мыши — механическая неисправность, при которой вместо одного нажатия кнопка отправляет два сигнала с очень коротким интервалом (~70 мс). Это приводит к:

- ❌ Случайному открытию/закрытию окон
- ❌ Выделению текста вместо одиночного клика
- ❌ Двойным отметкам в чекбоксах
- ❌ Случайным запускам программ
- ❌ Раздражающим ошибкам в работе

## Решение

MouseFix перехватывает события мыши на **системном уровне** с помощью низкоуровневого хука Windows (`WH_MOUSE_LL=14`) и блокирует повторные клики, если интервал между ними меньше заданного порога.

### Как это работает

```
Клик 1 ─────────────────────► Приложение ✅
                                (интервал > порога)
Клик 2 ─────────────────────► Приложение ✅
                               
Клик 1 ──────────► Блокировка 🛑
                   (интервал < порога)
Клик 2 ──────────► Блокировка 🛑
```

1. **Перехват** — хук мыши перехватывает каждое нажатие до того, как оно достигнет приложения
2. **Анализ** — измеряется интервал между текущим и предыдущим нажатием
3. **Блокировка** — если интервал меньше порога, событие уничтожается на системном уровне
4. **Пропуск** — нормальные клики проходят без задержки

### Управление

- **Переключатель** — включение/выключение блокировки
- **Ползунок** — настройка порога от 10 до 300 мс
- **Поле ввода** — точное значение с клавиатуры (Enter)
- **Пресеты** — быстрый выбор режима
- **Закрытие** — сворачивает в трей (блокировка продолжается)
- **Трей** — правый клик → показать окно или выйти

## 🔧 Технические детали

### Архитектура

```
┌─────────────────────────────┐
│         MouseFix            │
│  ┌───────────────────────┐  │
│  │   GUI (customtkinter) │  │
│  │   Tkinter mainloop    │  │
│  └──────────┬────────────┘  │
│  ┌──────────▼────────────┐  │
│  │  Windows Hook         │  │
│  │  WH_MOUSE_LL=14       │  │
│  │  SetWindowsHookExW()  │  │
│  └──────────┬────────────┘  │
│  ┌──────────▼────────────┐  │
│  │  CallNextHookEx()     │  │
│  │  return 1 = BLOCK     │  │
│  └───────────────────────┘  │
└─────────────────────────────┘
```

### Почему WH_MOUSE_LL?

Библиотека `pynput` не может блокировать события на уровне ОС — она только слушает. Для реальной блокировки используется низкоуровневый хук Windows:

- **`WH_MOUSE_LL (14)`** — глобальный хук мыши
- **`CallNextHookEx()`** — передача события дальше
- **`return 1`** — блокировка события (не доходит до приложений)
- Требует прав администратора
